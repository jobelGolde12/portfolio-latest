# Portfolio Redesign Plan

**Design spec**: `new-design.md` (Sections 0-20)
**Constraint**: Additive — all existing content preserved, restyled/restructured (never deleted)
**Stack**: Next.js 16, React 19, Tailwind CSS v4, Framer Motion

---

## Phase 1: Design Tokens + Global Styles

**Goal**: Replace current ad-hoc CSS custom properties with the full token system from Section 19. Every subsequent phase pulls from these tokens.

### Files to modify:
- **`app/globals.css`** — Replace current `:root` variables with Section 19's complete token set (colors, typography, spacing, radius, shadows, motion, opacity, blur). Add `[data-theme="light"]` block for light mode overrides. Add light/dark mode toggle logic via `data-theme` attribute. Update `@theme inline` to reference new tokens. Add `--font-fraunces` alongside existing font vars. Replace the current spacing scale (80px grid) with the spec's 4/8px system. Keep `scrollbar-hide`, existing keyframes, and `prefers-reduced-motion` rule (update animation overrides to match new motion tokens).
- **`app/layout.tsx`** — Swap `Instrument_Serif` import for `Fraunces` from `next/font/google` with weights `400;500;700;800;900` and variable `--font-fraunces`. Keep GeistSans and GeistMono. Add `<html data-theme="dark">` default. Keep skip link, CustomCursor, AnimatedBackground, Navbar, main wrapper. Remove FloatingTriangles import (will be removed later as it doesn't fit new vision).

### New files:
- **`components/ThemeProvider.tsx`** — Client component that reads `prefers-color-scheme` on mount, sets `data-theme` on `<html>`, provides toggle function via context. Respects system preference by default, persists manual choice to localStorage.

### Effort: Medium

## Phase 2: Component Library Primitives

**Goal**: Build/restyle the core UI primitives from Section 8 that every section will compose.

### Files to modify:
- **`components/ui/button.tsx`** (new) — Variants: primary (filled accent-signal), secondary (outlined border-strong), ghost (text-only). Sizes: sm (32px), md (40px), lg (48px). States: hover (bg-surface-2 + translateY(-1px)), active (scale 0.98), focus-visible (2px accent-signal ring), disabled (40% opacity).
- **`components/ui/card.tsx`** (new) — Base: bg-surface, border-subtle 1px, radius-lg, padding 24px. Hover state: border-strong, translateY(-2px), shadow deepens.
- **`components/ui/badge.tsx`** (new) — Status badge with dot indicator. Uses success/warning/accent-warm/text-tertiary colors. E.g., "● Available", "● Shipped".
- **`components/ui/pill.tsx`** (new) — Filter/category oriented. Neutral bg-surface-2, becomes accent-signal-tinted when active/selected.
- **`components/ui/tag.tsx`** (new) — Mono-font, small, for tech-stack labels on project cards.
- **`components/ui/input.tsx`** (new) — bg-surface, border-subtle, radius-md, 44px min height, label always visible above field, focus ring matches button.
- **`components/ui/tooltip.tsx`** (new) — 200ms delay, dismissible via Escape, never sole copy of essential info.
- **`components/ui/dialog.tsx`** (new) — Centered modal with backdrop blur, focus trap, close on Escape + backdrop click. Used for command palette.

### Effort: Medium

## Phase 4: Hero Redesign

**Goal**: Build Section 4's hero — the highest-leverage section. Status line signal motif, headline as precise claim, rotating subtitle, terminal artifact, two CTAs.

### Files to modify:
- **`components/Hero.tsx`** — Complete rewrite of content and layout while preserving existing data (name, location, contact). Structure:
  1. **Status line**: pulsing accent-signal dot + "Available for new roles — usually replies within a day." (Section 4's signal motif first appearance)
  2. **Headline**: "I build systems that stay boring under load." (serif font at text-5xl/text-6xl)
  3. **Rotating subtitle**: crossfade between 2-4 specializations ("full-stack web apps", "developer tooling", "community systems", "REST APIs")
  4. **Terminal artifact**: small monospace panel that types `whoami` → returns one-line bio. `curl status` → returns availability. Runs once on load, respects prefers-reduced-motion (shows final state immediately), aria-live="polite"
  5. **Two CTAs**: Primary "See projects" (links to #projects), Secondary "Get in touch" (links to #contact) or résumé download
  6. **Tech stack preview**: small monospace chips below CTAs (5-6 most relevant tools)
  7. **Profile image**: keep existing photo, smaller, subtle, not the focal point

### New files:
- **`components/TerminalArtifact.tsx`** — Self-contained typing terminal component. Config array of commands/responses. Types characters with 50ms delay. Respects prefers-reduced-motion. `aria-live="polite"` with static text fallback.

### Effort: Large

## Phase 11: Motion System

**Goal**: Implement Section 9's motion vocabulary — scroll reveals, micro-interactions, signal pulse, reduced-motion fallbacks.

### Files to modify:
- **`app/globals.css`** — Add motion keyframes: `signalPulse` (2.4s ambient opacity/scale), `shimmer` (skeleton loading). Update `prefers-reduced-motion` to handle new animations.
- **All section components** (Hero, About, Skills, Projects, Contact, Footer, Timeline) — Wire scroll-reveal animations using Framer Motion's `useInView` with new timing: 400-500ms duration, `cubic-bezier(0.16, 1, 0.3, 1)` easing, 40-60ms stagger, max ~6 staggered items. All respect `prefers-reduced-motion` (instant opacity swap).
- **`components/Hero.tsx`** — Signal pulse on status dot (continuous 2.4s cycle). Magnetic button on primary CTA (spring-based, 6-8px displacement cap).
- **`components/ui/button.tsx`** — Hover: 120-160ms ease-out translateY(-1px). Active: scale 0.98. Focus: 2px ring.
- **`components/ui/card.tsx`** — Hover: 200ms ease-out translateY(-2px) + shadow deepen.

### New files:
- **`components/ScrollReveal.tsx`** — Reusable wrapper component that applies scroll-reveal animation with configurable delay, direction (up/left/right), and stagger index. Handles prefers-reduced-motion internally.

### Effort: Medium

## Phase 14: Accessibility Hardening

**Goal**: Section 14 — Full a11y pass. Verify and fix all contrast, keyboard, focus, and semantic issues.

### Files to modify:
- **All components** — Audit and fix:
  - Every text/background pairing passes WCAG AA (4.6:1 normal, 3:1 large text)
  - Every interactive element has visible focus ring (2px accent-signal)
  - Semantic HTML: `<nav>`, `<main>`, `<section>`, `<article>`, `<button>`, `<a>`, heading levels in correct order
  - One `<h1>` per page (in Hero)
  - Section headings: `<h2>` for major sections
  - `aria-label` on icon-only buttons
  - Command palette follows combobox/listbox pattern
  - Contact form: visible labels, error text via `aria-describedby`
  - Status badges: color + text label (never bare colored dot)
  - Skip link: verify it works with new layout

### Effort: Medium

## Phase 16: Performance Hardening

**Goal**: Section 15 — Meet Core Web Vitals targets.

### Files to modify:
- **`components/Hero.tsx`** — Hero headline is LCP element (text, not image). Preload critical fonts. No render-blocking scripts above fold.
- **`components/TerminalArtifact.tsx`** — Lazy-load only when in viewport (intersection observer). Dynamic import in Hero.
- **`app/layout.tsx`** — Font preload for Fraunces weights actually used (400, 700, 800). `font-display: swap` on all fonts.
- **All images** — Explicit width/height or aspect-ratio to prevent CLS. Native `loading="lazy"` for below-fold images.
- **`components/AnimatedBackground.tsx`** — Verify transform/opacity-only animation (no layout-triggering properties).

## Verification Plan

After each phase, run:
1. `npm run build` — verify no TypeScript/build errors
2. `npm run dev` — visual check in browser at localhost:3000
3. Manual keyboard navigation test (Tab through all interactive elements)
4. Check `prefers-reduced-motion` by enabling in browser dev tools

After all phases:
1. Lighthouse audit — target: Performance ≥95, Accessibility ≥95
2. axe DevTools — zero critical/serious violations
3. Screen reader test (VoiceOver or NVDA) — all content accessible
4. Mobile responsive check (320px → 1440px)
5. Light/dark mode toggle verification
6. Command palette keyboard navigation test
